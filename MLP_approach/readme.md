# Task Scheduling on Multi-CPU Graph Architectures using Supervised Policy Learning

A research-oriented experimental study investigating supervised learning approaches for task scheduling on graph-based multiprocessor architectures.

This project explores the limitations of dense Multi-Layer Perceptrons (MLPs) for dynamic graph scheduling problems and motivates the use of graph-aware architectures such as Graph Neural Networks (GNNs).

# Overview

The objective of this project is to study how machine learning models can learn scheduling policies for multiprocessor systems where tasks are represented as Directed Acyclic Graphs (DAGs).

The environment simulates:
- task dependency graphs,
- CPU communication topologies,
- discrete scheduling decisions,
- execution dynamics over time.

A heuristic scheduling policy is first used to generate supervised training data through behavior cloning. A dense MLP model is then trained to imitate this heuristic policy.

The experiments highlight:
- successful local heuristic imitation,
- dataset imbalance issues,
- WAIT policy collapse,
- and poor structural generalization on unseen graph topologies.

# Environment Design

## Task Graph

Tasks are represented using Directed Acyclic Graphs (DAGs):

- nodes represent tasks,
- edges represent dependency constraints.

Each task contains:
- execution duration,
- dependency list,
- dependent tasks,
- execution state.

Task states:
- `pending`
- `in_progress`
- `completed`

---

## CPU Graph

Processors are modeled as graph structures:

- nodes represent CPUs,
- edges represent communication links.

The topology influences scheduling behavior and processor locality.

Each CPU contains:
- current assigned task,
- remaining execution time.

---

# Scheduling Policy

The heuristic scheduling policy prioritizes:

- tasks with many dependents,
- longer execution durations,
- CPUs with fewer busy neighbors.

A small amount of random noise is introduced during scoring to diversify scheduling trajectories.

---

# Dataset Generation

The dataset is generated by simulating multiple scheduling environments using deterministic seeds.

For each simulation step:

1. the environment state is encoded,
2. the heuristic policy computes the scheduling action,
3. the `(state, action)` pair is stored.

The final dataset is used for supervised behavior cloning.

---

# State Encoding

Since MLPs require fixed-size inputs:

- task graphs and CPU graphs are flattened,
- padding is applied,
- all features are normalized.

The final input vector contains:

- task features,
- CPU features,
- execution states,
- dependency information,
- topology-related features.

---

# MLP Architecture

The scheduling model is implemented using a dense Multi-Layer Perceptron:

```text
Input Layer (175)
        ↓
Linear(175 → 256)
        ↓
ReLU
        ↓
Linear(256 → 256)
        ↓
ReLU
        ↓
Linear(256 → N_actions)
```

Training configuration:

- CrossEntropyLoss
- Adam optimizer
- Learning rate: `0.001`

## Unseen Scheduling Scenarios

Generalization performance degraded significantly on unseen graph structures.

Main observed limitations:

- flatten vector representation,
- poor structural generalization,
- permutation sensitivity,
- dynamic action space constraints.

These observations motivate future work using Graph Neural Networks (GNNs).

---

# Current Limitations

The current implementation relies on:

- fixed-size flattened representations,
- static action encoding,
- dense MLP architectures.

As a result, the model struggles to:

- generalize across unseen graph topologies,
- reason over relational graph structures,
- scale to highly dynamic scheduling environments.
